# Unrouted VLED local placement check, 2026-10-06

The source is the [unlinked converter schematic](../../hardware/coupon/rev-a/staging/vled-converter.kicad_sch) and its [separate local KiCad placement](../../hardware/coupon/rev-a/staging/vled-layout-trial.kicad_pcb). This is **not** the coupon or final-board PCB. No board exists and no hardware measurement or firmware revision applies.

KiCad's bundled Python 3.9 regenerated the placement deterministically from the current 13-part / 39-logical-pin native XML netlist, exact project-local footprints and the [fit-screen coordinates](../../mechanical/review/fit-trial.json). A saved-board round trip checked all thirteen references, footprint library IDs, orientations, centres and numbered pad nets. The current file SHA-256 is `91a4a00868029bf169e9e088ced720954c892c12ca0bfa351660da6625eb5261`; successive generation was byte-stable before the silkscreen-reference visibility correction. KiCad CLI 10.0.6 loaded and plotted the actual copper pads and courtyards; the output was visually inspected. The local board has no tracks, vias or copper zones. Reference fields are hidden on this local trial because their final positions belong to full-board silkscreen placement.

The sandboxed standalone `kicad-cli pcb drc` aborted with exit 134 before creating a report, also on a one-footprint control board. The macOS crash log shows the DRC path calling AppKit mouse-position code before the abort. Running KiCad CLI with desktop access succeeded. The [raw native DRC report](vled-layout-drc-2026-10-06.json) has **zero geometry violations** and **thirty unconnected items** on the local, unrouted study. The latter are expected because no tracks or zones exist; this is **not** a complete-board DRC pass. The root coupon schematic still has zero configured ERC violations and 410 components / 1,537 logical pins. Those are different checks.

Its local DRC reports zero geometry violations and twenty remaining open connections.
